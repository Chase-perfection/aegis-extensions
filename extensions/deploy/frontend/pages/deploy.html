    Connect GitHub

    Aegis registers its own GitHub App. You confirm it on GitHub, choose which repositories it may read, and no personal access token is ever stored here.

    An App belongs to the account it is created under, and it can only be installed there. Leave this empty when the repositories are yours; name the organisation when they belong to one, or its private repositories will stay invisible.

    Connect GitHub

    Register an App by hand

    For a server GitHub cannot reach, create the App yourself on github.com with the webhook left unchecked, then paste what it gives you. Aegis checks the pair against GitHub before storing it. Cloning needs only outbound HTTPS, and pushes are picked up by polling the branch.

    1. Open github.com, Settings, Developer settings, GitHub Apps, New GitHub App.
    2. Name it, put any homepage URL, and untick Active under Webhook so no address is required.
    3. Under Repository permissions set Contents to Read-only and Metadata to Read-only, then create the App.
    4. On the App page, note the App ID and use Generate a private key, which downloads a .pem file.
    5. Install the App on your account and choose the repositories it may read.

    Authentication

    Not configured

    A deployed site answers on its own port to anyone who can reach it. Each site below picks how it asks who is knocking: nothing at all, or a login against your directory. The directory is configured once here and then chosen per site, where each site can also be moved to HTTPS. Aegis never stores a user password; it checks each login against the directory.

    Active Directory accepts CORP\svc-aegis, svc-aegis@corp.local or the full distinguished name. Any of the three works here. Leave it empty for an anonymous bind, which most directories refuse.

    Advanced settings Search base, filter, groups, certificate validation

    Off by default. Active Directory lists neither the groups a user reaches through another group nor their primary group, usually Domain Users, so a parent group typed below would refuse everyone. Turning this on asks the domain controller for the full list, which can only let more people in. It does nothing on a directory that is not Active Directory.

    A login lasts eight hours. Without this, someone removed from an allowed group keeps their access for the rest of it. 0 turns the re-check off. If the directory cannot be reached the session is kept, so a controller that is briefly down does not empty every site.

    Leave this on. If the controller presents a certificate Aegis does not trust, the page offers to trust that authority, which keeps the check and fixes the cause. Turning it off accepts any certificate on a connection that carries the password above.

    The address, the search base, the filter and the bind template all follow from the domain name, and the last audit already named it. Fill in what Aegis knows writes those into the fields left empty and touches nothing else, so a value you typed stays. The service account and its password cannot be guessed, and nothing is stored until you save.

    Test with a real account

    Saving already checks that Aegis can reach the directory and bind the service account. This checks one person: it lists the groups the directory returns for them, which are the only values a site's allowed groups will ever match. The password is used once and stored nowhere.

    Environment variables
